# DB構築ツール 機能ロードマップ

Rust + GPUI で作るデータベース構築ツール。最初は SQL Server を対象にする。

## ゴール

- **A(初期リリース)**: 画面でテーブルを設計し、DDLを生成・実行する
- **B(後続)**: 既存DBを読み取り、構造を一覧・編集する

## 設計原則

- **AとBは同じスキーマモデルを共有する。** Bは「DBを読んでモデルを作る入口」を足すだけにする
- **`core` はUIにもDBにも依存しない。** スキーマモデルとDDL生成だけを持つ
- **DB方言は `core` の中で閉じる。** 将来PostgreSQLなどを足す時はここに方言を追加する
- **接続なしでも使える。** 設計・保存・DDLプレビューまでは、DBに繋がなくても動く

## クレート構成

| クレート | 役割 | 主な依存 |
|---|---|---|
| `core` | スキーマモデル、DDL生成、差分計算、JSON保存 | serde, serde_json |
| `db` | SQL Server接続、DDL実行、カタログ読み取り | tiberius, tokio, tokio-util |
| `app` | GPUIの画面、`core`と`db`の連携 | gpui, gpui-component |

注意: tiberiusはtokio前提、GPUIは独自executor。別スレッドでtokioランタイムを動かし、結果をチャネルで画面側に返す。

## Phase 1: スキーマモデルとDDL生成(core)

目的: 画面なしで「モデル → DDL」が完成している状態にする。

### モデル

- [ ] テーブル(スキーマ名、テーブル名)
- [ ] カラム(名前、型、NULL可否、IDENTITY、DEFAULT)
- [ ] 主キー(複合キー対応)
- [ ] 外部キー(複合キー対応、参照先テーブル・カラム)
- [ ] インデックス(UNIQUE有無、複数カラム)
- [ ] `Schema`(テーブル集合)全体
- [ ] `PartialEq` / `Clone` / `Debug` / `Serialize` / `Deserialize` を付与

### 対応するSQL Serverの型(最初の範囲)

- [ ] INT, BIGINT, BIT
- [ ] DECIMAL(p, s)
- [ ] NVARCHAR(n) / NVARCHAR(MAX)
- [ ] DATETIME2
- [ ] UNIQUEIDENTIFIER

### DDL生成

- [ ] `CREATE TABLE`(PK含む)
- [ ] FKは `ALTER TABLE ... ADD CONSTRAINT` で後から付ける(テーブルの依存順を計算しなくて済む)
- [ ] `CREATE INDEX`
- [ ] 識別子のクォート(`[ ]`、中の `]` は `]]` にエスケープ)
- [ ] `GO` は出力しない(クライアントの区切り文字でありT-SQLではないため)

### 検証(バリデーション)

- [ ] テーブル名・カラム名の重複チェック
- [ ] PK・FK・インデックスが存在しないカラムを参照していないか
- [ ] FKの参照先テーブル・カラムが存在するか、型が一致するか
- [ ] 空の名前、SQL Serverの識別子長(128文字)の超過

### テスト

- [ ] 期待するDDL文字列を先に決めて書く(スナップショット的に)
- [ ] 不正なスキーマがエラーになるテスト

**完了条件**: テストだけで、複数テーブル・FK・インデックス付きのDDLが正しく出力される。

## Phase 2: 設計画面(app)— Aの中核

目的: 画面でスキーマを編集できる状態にする。まだDBには繋がない。

### レイアウト

- [ ] 左: テーブル一覧
- [ ] 中央: 選択中テーブルのカラム編集グリッド
- [ ] 右または下: DDLプレビュー

### テーブル操作

- [ ] テーブルの追加・削除・名前変更
- [ ] テーブルの複製

### カラム編集

- [ ] カラムの追加・削除・並べ替え
- [ ] 名前、型、長さ・精度、NULL可否、IDENTITY、DEFAULT の編集
- [ ] 主キーの指定(複数選択)

### 制約・インデックス編集

- [ ] 外部キーの追加・編集・削除(参照先をドロップダウンで選ぶ)
- [ ] インデックスの追加・編集・削除

### 編集体験

- [ ] 編集のたびにDDLプレビューを再生成
- [ ] バリデーションエラーを該当箇所に表示
- [ ] Undo / Redo
- [ ] キーボード操作(Tabでセル移動、Enterで確定など)

**完了条件**: 画面だけでテーブルを複数作り、FKを張り、正しいDDLがプレビューに出る。

## Phase 3: プロジェクト保存

目的: 接続なしでも「設計して保存するツール」として使えるようにする。

- [ ] プロジェクトをJSONで保存・読み込み
- [ ] ファイルのバージョン番号を入れる(将来の形式変更に備える)
- [ ] 未保存の変更がある時の確認ダイアログ
- [ ] 最近開いたプロジェクトの一覧
- [ ] DDLを `.sql` ファイルとして書き出す

**完了条件**: 保存したファイルを開き直すと、完全に同じ状態が復元される。

---

## Phase 4: SQL Server接続と実行(db)— A完成

目的: 生成したDDLを実際のDBに適用できるようにする。

### 接続

- [ ] 接続設定(サーバー、ポート、DB名、認証方式)
- [ ] SQL Server認証 / Windows認証
- [ ] 接続テスト
- [ ] 接続情報の保存(パスワードはOSのキーストアなど、平文のJSONには入れない)

### 実行

- [ ] DDLを1文ずつ実行する
- [ ] `BEGIN TRAN` で囲み、失敗したら `ROLLBACK`(SQL ServerはDDLもトランザクションに入れられる)
- [ ] 実行前の確認ダイアログ(対象サーバー・DB名・実行するSQLを表示)
- [ ] 進捗とエラーの表示(どの文で失敗したか)
- [ ] 実行ログの保存

### 安全策

- [ ] 接続先が本番かどうかのラベル付けと、本番では追加確認
- [ ] 既存オブジェクトと衝突する場合の事前警告

**完了条件**: 空のDBに対して、設計したスキーマ全体を1回の操作で作成できる。失敗時は何も残らない。

**→ ここが初期リリース(A)。**

## Phase 5: 既存DBの読み取り(B-1)

目的: 既存DBの構造を、同じモデルとして画面に表示する。

- [ ] カタログビュー(`sys.*` / `INFORMATION_SCHEMA`)からテーブル・カラム・PK・FK・インデックスを読む
- [ ] 読み取った結果を `Schema` に変換する(Phase 1と同じモデル)
- [ ] 画面で閲覧する(Phase 2のUIをそのまま使う)
- [ ] 未対応の型・機能(計算列、パーティションなど)は、読み取れない旨を明示して保持しない
- [ ] 読み取ったスキーマをプロジェクトとして保存

**完了条件**: 既存DBを読み込み、画面で構造を確認できる。

---

## Phase 6: 差分とALTER(B-2)

目的: 既存DBを編集し、変更分だけをDBに反映する。

- [ ] 「元のスキーマ」と「編集後のスキーマ」の差分計算
- [ ] 差分からの `ALTER` 文生成
  - [ ] カラムの追加・削除・型変更・NULL可否変更
  - [ ] 制約・インデックスの追加・削除
  - [ ] テーブルの追加・削除・名前変更
- [ ] 危険な変更の警告(データ損失の可能性、長さの縮小、NOT NULL化など)
- [ ] 差分のプレビュー画面
- [ ] ドリフト検出(読み取り後にDB側が変更されていないか、実行前に再確認)

**完了条件**: 既存DBのカラムを編集し、生成された `ALTER` が安全に適用される。
